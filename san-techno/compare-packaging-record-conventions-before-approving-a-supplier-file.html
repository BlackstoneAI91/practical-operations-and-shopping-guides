Compare Packaging Record Conventions Before Approving a Supplier File

Published by San Techno.

A practical guide for Singapore procurement teams on comparing how suppliers record packaging dimensions, unit versus outer packaging, and where confirmed fields and their evidence should sit before a supplier file is approved.

Why packaging record conventions need comparing before approval

A supplier file can look complete and still be hard to use. The purchase reference is there, the lot description is there, and the dimensions are filled in. What is often missing is agreement on what those dimension fields actually describe. One supplier may enter the size of the individual unit inside the shipment. Another may enter the size of the outer package that arrives at the dock. A third may enter both, but in a single free-text field with no label. If your team approves the file without noticing the difference, the record becomes a source of quiet confusion later, when someone tries to compare two offers or check a delivery against what was ordered.

This guide is written for Singapore procurement teams sourcing, receiving and documenting semiconductor and solar materials. It focuses on three questions: where dimensions are entered, whether a record describes the unit or the outer packaging, and how to keep confirmed fields attached to the correct evidence. It does not describe packing methods or recommend any physical handling. The aim is administrative: to make the paperwork comparable before anyone signs it off.

That breadth is a useful reminder that a single buying team may hold files for very different material types, each with its own record habits. The conventions you compare should be yours, applied consistently, rather than copied from whichever supplier sent the most recent file.

Start with a field map, not a form

Before comparing two supplier files, write down the fields you expect to see and what each one is supposed to mean. A field map is a short internal list, not a supplier form. It answers a simple question for every dimension entry: what does this number describe?

A workable field map for packaging records usually separates four things:

Unit dimensions. The size of the individual item or inner unit as the supplier describes it. Outer package dimensions. The size of the package as it arrives, described in the supplier's own terms. Quantity basis. Whether the quantity in the file counts units, packages, or something else, and which of those the dimensions relate to. Evidence reference. The document, revision or confirmation that supports the entry.

The point of the map is to stop a single unlabelled field from carrying two meanings. When you compare a new supplier file against your map, you are not judging whether the supplier is right. You are checking whether the file can be read the same way by two people on your team. If it cannot, that is a documentation gap to raise before approval, not after.

Keep the map short enough to use. A one-page list that buyers actually open beats a detailed standard that sits unread.

Unit or outer packaging: the distinction that causes most confusion

The most common mismatch in packaging records is not a wrong number. It is a number attached to the wrong subject. A file may say "dimensions" and give figures that could describe either the unit or the outer package, and nothing in the record settles which.

A practical way to compare conventions is to ask, for each supplier file, three plain questions:

Does the file label the dimension field as unit or outer package, or leave it unlabelled? If both are present, are they in separate fields, or combined in one text entry? Does the quantity field make clear which subject the dimensions belong to?

Where a file leaves the subject unlabelled, record that as an open question rather than guessing. Guessing is how a unit dimension ends up compared against an outer package dimension from a different supplier, and the comparison then means nothing. The fix is not to pick the more likely reading. The fix is to ask the supplier to confirm, in writing, what the entry describes, and to note the confirmation against the field.

This is administrative discipline, not technical judgement. You are not assessing whether a package is suitable. You are making sure the record says what it is about.

Where dimensions are entered matters as much as what they say

Two files can contain the same figures and still be unequal, because the figures sit in different places. One supplier may put dimensions in a dedicated field in its specification sheet. Another may bury them in a description paragraph. A third may put them only in a covering note that is not part of the controlled document.

When you compare conventions, note the location of each dimension entry and whether that location is part of the document the supplier controls and revisions. A figure in a controlled field is easier to track across revisions than a figure in an email. If a dimension appears only in correspondence, treat it as provisional until it is reflected in the controlled document or explicitly confirmed as the record of truth.

A simple location log helps. For each supplier file, record:

Where the dimension entry sits (controlled field, description text, or correspondence). Whether that location is revised when the figure changes. Who at the supplier confirmed the entry, by role rather than by name.

The goal is that a colleague opening the file six months later can find the dimension, understand what it describes, and see where it came from. That is a documentation outcome, and it is achievable without any technical assessment of the material itself.

Keeping confirmed fields with the correct evidence

Approval should attach each confirmed field to the evidence that supports it. A confirmed dimension with no evidence reference is a claim waiting to be questioned. A confirmed dimension with the wrong evidence reference is worse, because it looks supported when it is not.

A short evidence pairing table keeps this honest. For each confirmed field, record the evidence identifier, the document revision, and the date the confirmation was received. Then check the pairing: does the evidence actually address the field it is attached to? A confirmation that a supplier sent a revised specification does not, by itself, confirm a particular dimension. Those are two different facts and should carry two different references.

This is where a controlled approach to supplier documentation pays off. San Techno's own materials work spans several fields, and the company notes that its power-module programme addresses heat movement, package stability and reliable operation under repeated electrical and thermal loading, while detailed architecture, materials, dimensions and assembly processes remain confidential. That is a useful illustration of a general point: some fields in a supplier file will be confirmed, and others will be explicitly out of scope. Your evidence table should be able to show which is which, so that an absent field is recorded as not provided rather than mistaken for a gap someone forgot to fill.

When a field is marked confidential or not provided, note that status against the field and move on. Do not infer a value to complete the table.

A comparison worksheet you can run in one sitting

The worksheet below is an author heuristic, offered as an example rather than a tested method. Adapt the columns to your team.

For each supplier file under review, complete one row per dimension field:

Field name as the supplier labels it. Subject: unit, outer package, or unclear. Location: controlled field, description text, or correspondence. Quantity basis stated? Yes or no. Evidence reference and revision. Status: confirmed, open question, or not provided. Owner of the follow-up, by role.

Then run three checks across the rows:

Subject check. Every dimension row has a subject. Any row marked unclear becomes an open question before approval. Location check. Every confirmed row points to a controlled location or an explicit confirmation, not to an unlabelled note. Evidence check. Every confirmed row has an evidence reference that actually addresses that field.

A worked fictional example: a file lists "size" with figures, no subject label, in a description paragraph, with no evidence reference. The worksheet records subject as unclear, location as description text, evidence as none, and status as open question. The follow-up is a written request to the supplier to confirm what the entry describes and to reflect it in the controlled document. The file is not approved until that row is resolved or explicitly accepted as open with a named owner.

This worksheet does not tell you whether a package is suitable for anything. It tells you whether the record is readable, attributable and complete enough to approve.

What to do when conventions cannot be reconciled

Sometimes two supplier files simply cannot be compared on packaging records, because one uses conventions the other does not. That is a finding, not a failure. Record it plainly: which fields could not be matched, why, and what would be needed to match them.

A few practical responses:

Ask for a written confirmation of the subject of each unclear dimension field, and file the reply against the field. Where a supplier will not confirm, mark the field as not provided and note the request and its date. Keep the original file and the comparison worksheet together, so the reasoning survives a change of buyer. Route unresolved fields to the role that owns the decision, rather than letting them sit in an inbox.
