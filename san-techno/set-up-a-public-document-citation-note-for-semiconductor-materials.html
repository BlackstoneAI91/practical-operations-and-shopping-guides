Set Up a Public-Document Citation Note for Semiconductor Materials Purchasing

Published by San Techno.

A practical guide for Singapore procurement teams on writing a citation note for a public product page and its access date, so the reference stays a public source record rather than a supplier quotation.

Why a citation note is not a quotation

A public product page is a description, not an offer. When a procurement team saves a page about semiconductor materials, the saved page tells you what a supplier says publicly about its categories and capabilities. It does not tell you price, lead time, stock, tolerance, packaging or contractual terms. Those come from a quotation or a written confirmation issued to your organisation.

The citation note exists to keep that distinction visible months later. It records which public page you read, when you read it, and what you understood from it, so a colleague opening the file does not mistake a marketing description for an agreed commercial position. San Techno, for example, is a Singapore-based company whose public site describes three branches of work: semiconductor silicon materials, silicon wafer reclaim services and AC-to-DC power module design. That is useful identity context for a supplier file. It is not a statement that any specific grade, volume or delivery is available to you.

A good rule is to write the note in the past tense about the page and in the future tense about your own next step. "The public page listed these categories on the date accessed" is a record. "The supplier will provide X at Y" belongs in a quotation file, not here. Keeping the two apart protects the buyer who inherits the file and the supplier who never agreed to the wording.

The fields a citation note should carry

A citation note works best when it is short and repeatable. The following fields are an author heuristic, not a standard, but they cover the questions a reviewer usually asks.

Source name: the public page or document you read, described in plain words rather than by address. Access date: the calendar date you viewed it, written in full. Reader: the person who opened the page. Purpose: why the page was consulted, for example an early category scan before a request for quotation. Extracted points: two or three short paraphrases of what the page said, in your own words. Limits: an explicit line stating that the page is not a quotation and carries no price, availability or specification commitment. Next action: who will request the authoritative document and by when.

Two further fields help in practice. A status field, such as "public reference only" or "superseded by quotation", stops an old note being reused as current evidence. A related-document field lets you point to the quotation or confirmation that later replaced the public reference, without copying its contents into the citation note.

Write the extracted points as paraphrase, not as copied text. Paraphrase forces you to notice what the page actually said, and it keeps the note readable when the original page changes or disappears.

Reading a public product page without over-reading it

Public pages are written to describe a business, and they often group several activities under one heading. A reader scanning for semiconductor materials may see silicon materials, wafer handling and prepared inventory listed together, and may reasonably ask which of these applies to a given enquiry. The page alone rarely answers that.

A disciplined reading separates three things. First, what the page states as a category or activity. Second, what it states as a development direction or programme, which is not the same as a catalogue item. Third, what it deliberately leaves out. San Techno's public material, for instance, notes that detailed architecture, materials, dimensions and assembly processes for its power-module work remain confidential. A citation note should record that boundary rather than trying to fill it. The correct next step is a direct question to the supplier, not an inference from a public heading.

Apply the same care to any figure or performance statement you encounter. If a page mentions a development concept, record it as a development concept. If it mentions a service area, record it as a service area. Do not upgrade a description into a commitment, and do not downgrade a stated activity into a guess. The note should be boringly accurate, because its only job is to be trustworthy later.

A worked example using fictional references

The following example is fictional and exists only to show the shape of a completed note.

Source name: public product page of a hypothetical supplier, category overview. Access date: 14 March. Reader: procurement associate. Purpose: initial category scan before deciding whether to request a quotation. Extracted points: the page describes a materials category, a handling-related service and a prepared-inventory listing; it also mentions a power-module design activity. Limits: the page is a public description only; no price, availability, grade or delivery commitment is recorded here. Status: public reference only. Next action: purchasing lead to request an authoritative specification document and a written quotation before any internal comparison.

Notice what the example does not do. It does not name a product as suitable for a project. It does not record a price. It does not claim the supplier holds stock. It does not describe how any material is processed. It simply fixes the public reference in time and assigns the next step to a named role.

A second fictional note might record that a page was revisited after a category heading changed, with the earlier note marked as historical and the new access date recorded separately. That habit keeps a clean trail when public pages are edited, which they routinely are.

Where the note sits in the procurement file

A citation note is a reference record, so it belongs with reference material rather than with commercial documents. A simple three-part structure works: a public references folder for citation notes, a commercial folder for quotations and confirmations, and a decisions folder for internal approvals. The citation note lives in the first and points to the second when a quotation arrives.

This separation matters when a file is handed over. A colleague opening the commercial folder expects agreed terms. A colleague opening the public references folder expects descriptions. Mixing them creates the exact confusion the note was meant to prevent.

It also helps to keep the note's own history. If you revise a citation note, record the revision date and what changed, rather than overwriting the earlier version silently. A short revision line such as "access date corrected; extracted points unchanged" is enough. Where a public page has been replaced, mark the old note as historical and create a new one rather than editing the old entry into something it never was.

Finally, decide who may add citation notes. A single owner per supplier file, with a named deputy, keeps the folder consistent without turning a simple record into a committee exercise.

Keeping the note honest about what the brand claims

A citation note should distinguish the supplier's public statements from your own conclusions. San Techno's public material states that it has advanced semiconductor and solar materials, specialised power-module designs and biological solutions since 2006, and that it began as a wholesaler and distributor of semiconductor- and solar-grade silicon materials. Those are the company's own public statements, and a citation note may record them as such, attributed to the public page and dated.

What the note should not do is convert a public statement into a verified fact about your order. A statement that materials can be processed into reusable raw materials for solar wafers and cells is a description of an activity, not a promise about your consignment. Record it as a described activity, with the access date, and let the quotation and any technical documents carry the commitments.

This habit also protects the supplier relationship. When a buyer's file accurately labels public descriptions as descriptions, later conversations about specification, volume and timing start from a shared understanding rather than from a disputed note. The note becomes a map of what was known and when, which is exactly what a procurement record should be.

A short worksheet before you save the note

Use this checklist as an author heuristic. It is not a compliance standard, and it does not replace your organisation's own record-keeping rules.

One: is the source described in plain words, without an address? Two: is the access date written in full and in the past? Three: are the extracted points paraphrased rather than copied? Four: does the limits line state clearly that the page is not a quotation? Five: is a next action assigned to a named role? Six: is the status field set, so the note cannot be mistaken for current commercial evidence? Seven: does the note avoid personal contact details, internal commentary and anything marked confidential? Eight: if a quotation already exists, does the note point to it rather than duplicate it?

If any answer is no, fix the note before saving it. A citation note that takes two minutes to correct now can save a longer conversation later, when someone asks why a public description was treated as an agreed term. The aim is modest: a short, dated, honest record that a colleague can trust without needing to reopen the page.
