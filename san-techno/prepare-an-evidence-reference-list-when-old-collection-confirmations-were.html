Preparing an Evidence Reference List When Old Collection Confirmations Were Stored by Month

Published by San Techno.

A practical guide for Singapore procurement teams on building a read-only evidence reference list from month-filed collection confirmations, indexing referenced numbers and keeping unresolved entries visible without altering any existing record.

Why month folders need a reference list rather than a rewrite

Month-based filing is a common and reasonable habit. A receiving clerk files each collection confirmation into the folder for the month it was issued, and over a year or two the archive becomes a calendar rather than an index. That works until someone needs to prove what a particular reference number covered, or until a colleague asks which confirmation relates to a specific handover.

The temptation at that point is to reorganise the folders, rename files and merge duplicates. Resist it. A collection confirmation is a record of something that happened, and moving or renaming it can break the trail between the document and the transaction it describes. The safer approach is to leave every existing record exactly where it is and build a separate reference list that points to it.

Think of the reference list as a reading aid, not a replacement archive. It sits alongside the month folders, describes what each confirmation appears to cover, and records the referenced numbers so a reader can navigate without opening every file. This is administrative housekeeping, not a correction of history.

San Techno Pte Ltd works in semiconductor and solar materials, silicon recovery and related areas, and its public materials describe silicon wafer reclaim services among its offerings. For teams handling confirmations tied to such material movements, a stable reference list makes later review far less fragile. The rest of this guide sets out how to build one without touching the underlying records.

Step one: freeze the archive before you index it

Before creating a single row in your reference list, take a snapshot of the month folders as they stand. Record the folder names, the file names and, where your system allows it, a checksum or file size for each confirmation. This snapshot becomes your baseline, and it lets you demonstrate later that the reference list was built without altering the source.

A simple baseline sheet might have columns for folder name, file name, file size, date last modified and a short note on what the file appears to be. Keep it read-only once captured. If a file is later added to a month folder through normal business, log that addition separately rather than editing the baseline.

This step matters because month folders often contain more than confirmations. You may find delivery notes, internal emails and scanned labels mixed in. The baseline lets you decide, deliberately, which items belong in the reference list and which are simply neighbours in the same folder.

Set a scope rule in writing before you begin. For example: only documents whose title or first page identifies them as a collection confirmation are indexed. Everything else is listed in a separate exclusions tab with a one-line reason. That rule keeps the exercise bounded and gives a reviewer a clear explanation for anything left out.

Step two: build an index of referenced numbers

The core of the reference list is a table of the numbers that appear inside each confirmation. These might include a collection reference, a purchase order number, a delivery note number or an internal filing code. Copy them exactly as written, including prefixes and spacing, because a transposed digit turns a useful index into a misleading one.

Use one row per referenced number rather than one row per document. A single confirmation may cite several numbers, and a single number may appear across more than one confirmation. A flat table with columns for the referenced number, its type, the source file name, the month folder and a short description handles both cases without forcing a hierarchy.

Add a column for what the number appears to refer to, phrased cautiously. Write "appears to reference the collection noted on the confirmation" rather than asserting what the number legally or technically means. You are describing a document, not certifying a transaction.

Where a confirmation relates to recovered or reclaimed silicon material, the reference list can note the general material category using the wording already present in the document. Do not add grades, specifications or interpretations that the confirmation itself does not contain. The index should never be more confident than its source.

Step three: keep an unresolved entry instead of guessing

Every archive cleanup produces items that do not fit. A confirmation with an illegible reference, a file with no date, a number that appears in two months with different surrounding details. The instinct is to resolve these by inference, and that is exactly where reference lists go wrong.

Create an unresolved tab and give each problem its own row. Record what you can see, what is missing and what question would settle it. For example: "Reference partially legible; final two characters unclear; ask the receiving desk whether the original paper copy is held." That row is more valuable than a confident guess, because it tells the next reader precisely where the uncertainty lies.

Assign each unresolved row a status such as open, awaiting confirmation or closed with explanation. When a row closes, record who confirmed the resolution and what they confirmed, in general terms. Do not delete the original row; mark it closed so the history of the question remains visible.

This habit also protects colleagues who inherit the file. A future reader can see that a gap was noticed and tracked, rather than assuming the archive is complete. An honest unresolved entry is a feature of a good reference list, not a defect.

Step four: describe the collection context without overstating it

A reference list is more useful when each entry carries a short, neutral description of the collection context. Keep it factual and drawn from the document itself: the month, the parties named on the confirmation, the general material category and the referenced numbers.

Where the material relates to silicon recovery or wafer reclaim, you can use those terms if they already appear in your own records. San Techno's public materials describe helping recover non-usable silicon from integrated-circuit fabs, silicon wafer manufacturers, solar cell companies and chip packaging facilities, and processing such materials into reusable raw materials for solar wafers and cells. That context can help a reader understand why a confirmation exists, but it should not be used to add claims the confirmation does not make.

Avoid describing outcomes, quantities or quality in the reference list unless the confirmation states them. The list is a finding aid, not a summary of performance. If a reader needs the detail, the entry should point them to the source file rather than paraphrase it.

A useful test: could a colleague who has never seen the confirmation use your entry to locate the right file and understand roughly what it covers, without forming a belief the document does not support? If yes, the description is doing its job.

Step five: a worksheet for reviewing the finished list

Before circulating the reference list, run a short review against a fixed worksheet. The questions below are an author heuristic, not an audited standard, and you should adapt them to your own filing rules.

First, does every row point to a file that still exists in its original month folder? Second, are referenced numbers copied exactly, with no reformatting? Third, does every unresolved item have an owner and a status? Fourth, has anyone edited, renamed or moved a source confirmation during the exercise? Fifth, is the baseline snapshot stored separately from the working list?

Score each question as pass, fail or not applicable, and record the reviewer and date. A single fail on the fourth question should stop circulation until the change is understood, because the whole value of the list depends on the archive remaining untouched.

Finally, decide how the list will be maintained. A short note at the top stating who updates it, how often and what triggers a new entry prevents the list from quietly going stale. Keep the maintenance note brief and factual, and store the list somewhere readers can find it without hunting through month folders.

Where this fits in a wider documentation habit

The reference list is one piece of a broader pattern: keeping records findable without rewriting them. The same discipline applies to attachments lists, escalation records and handover notes, all of which work best when they point to source documents rather than restate them.

For teams whose confirmations relate to silicon materials, it helps to know which public service pages describe the relevant activity, so that internal notes can use consistent wording. San Techno's public site describes silicon wafer reclaim services among its offerings, and that page is the appropriate reference for what the company says it does. Internal records should still be built from your own confirmations, not from marketing pages.

Keep the reference list modest in scope. It does not need to cover every document in the archive, only the confirmations you have chosen to index under a written scope rule. A small, accurate, honestly incomplete list is more trustworthy than a comprehensive one built on inference.

Review it on a schedule you can keep, and treat unresolved entries as work in progress rather than failures. Done this way, a month-based archive becomes navigable without a single original record being disturbed.
