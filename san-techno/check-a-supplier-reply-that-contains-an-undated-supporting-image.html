Check a supplier reply that contains an undated supporting image

Published by San Techno.

A practical guide for Singapore procurement teams on separating a product illustration from a material specification when a supplier reply includes an undated supporting image, with follow-up wording and file-context steps.

Why an undated image in a supplier reply needs its own check

A supplier reply often arrives as a short message with a picture attached. The picture may show a wafer, a package, a drum or a printed sheet. It looks like evidence, so it is easy to treat it as part of the answer. The safer reading is narrower: an undated image is an illustration until someone confirms what it shows, when it was produced and which document it belongs to.

Your job in procurement is not to judge whether the image is technically correct. It is to keep the record honest. That means separating three things that a single reply can blur together: the supplier's written statement, the image as a file, and the specification document that actually governs the material. If the image has no date, no caption and no reference number, you cannot tell whether it describes a current product, an older version or something else entirely.

This matters across semiconductor materials, where a picture of a wafer or a package can be read in several ways depending on context. Treat the image as a prompt for a question, not as a substitute for an answer. The rest of this guide sets out how to separate the illustration from the specification, how to write the follow-up, and how to retain the file context so a colleague can retrace your reasoning later.

Separate the illustration from the specification

Start by labelling what you actually received. A supplier reply with an image usually contains four elements: the message text, the image file, any file name, and any document the message refers to. Write each one down separately before you form a view.

A simple worksheet works well here. Create four columns: element received, what it appears to show, what it does not establish, and the open question. For the image, the third column is usually the longest. A picture of a packaged module does not establish a part number, a revision, a date or a specification. A picture of silicon material does not establish grade, source or handling history.

Keep the specification question separate from the illustration question. If your file already holds an approved specification document, the image is at most a secondary illustration and should be marked as such. If no specification is on file, the image does not fill that gap. It only tells you that the supplier chose to send a picture.

This is a documentation discipline, not a technical comparison. You are not asked to decide whether the image matches the material. You are asked to record that the image exists, that it is undated, and that the authoritative description still has to come from a named document.

Write the follow-up question in plain terms

The follow-up should be short and specific. Avoid asking the supplier to confirm that the image is correct, because that invites a yes that carries no record value. Ask instead for the document the image belongs to, and for the details that make the image traceable.

A workable pattern is: thank the supplier for the reply, note that the attached image has no date or reference, and ask three questions. First, which document or product sheet does the image belong to, including its reference and revision. Second, what date was the image produced or last updated. Third, is the image intended to illustrate a current offering or an earlier one. Add a line asking the supplier to confirm in writing which specification document should be treated as authoritative for the material in question.

Keep the wording neutral. You are not challenging the supplier's competence; you are closing a record gap. If the reply concerns a specialised area such as power module development, the same three questions still apply, because the image is a file with a history regardless of the subject.

Where the supplier has a public product page, you can note the page as context, but do not treat a web page as a substitute for the supplier's written confirmation. The public pages describe what a company offers; they do not date an individual image.

Retain the file context, not just the file

Saving the image is the easy part. The harder part is saving enough context that someone else can understand why it is in the folder. A file with a generic name and no note becomes an orphan within weeks.

Use a small context note alongside the image. Record the date you received it, the message it arrived with, the sender's organisation, the material or request it relates to, and the fact that it was undated at receipt. Record what you asked and what came back. If the supplier later sends a dated document, link the two in the note rather than replacing the image.

Keep the image in the same file as the written reply, not in a general pictures folder. The pairing is the point: the image only means something in the context of the message that carried it. If your team uses a shared drive, name the file with the request reference and the receipt date so it sorts sensibly.

Finally, mark the status clearly. An image awaiting a dated source is not the same as an image that has been matched to a specification. Use a plain status label such as pending source, and leave it visible until the supplier's written confirmation arrives.

Where public product information fits, and where it does not

Public product pages are useful for orientation. They tell you what a company says it works on, which helps you frame a question and route it to the right person. For example, San Techno describes its work across semiconductor silicon materials, silicon wafer reclaim services and AC-to-DC power module design, and its public pages set out those areas as separate branches. That is helpful context when you are deciding which part of a supplier's offering your question belongs to.

What public pages cannot do is date an image or confirm that a specific picture matches a specific material. A page may describe a development direction, such as an intelligent IGBT power-module concept centred on double-sided cooling, while the detailed architecture and materials remain confidential. That is a normal boundary. It means the public description orients you, and the supplier's written reply carries the record.

Use the public page to check that you are asking the right team, and use the reply to check what was actually said. Keep the two in separate fields in your note. If a colleague later asks why you approached a particular team, the public page explains the routing; the reply explains the substance.

A short decision checklist before you file the reply

Before you close the item, run through a short checklist. It is an author heuristic, not a standard, and you should adapt it to your own file rules.

One: is the image dated, captioned or referenced? If not, it stays an illustration. Two: does your file already hold an authoritative specification document? If yes, note the image as secondary. If no, the gap remains open. Three: have you asked which document the image belongs to, when it was produced, and whether it is current? Four: is the written reply saved with the image in the same place? Five: does the context note record the receipt date, the request reference and the open question? Six: is the status label visible and accurate?

If any answer is no, the item is not ready to file as complete. That is not a failure; it is an accurate record of where the check stands. A pending item with a clear question is more useful than a closed item with an unexplained picture.

Keep the checklist short enough that you will actually use it. Three or four lines in the file note are usually enough.

Keeping the record consistent across the team

The same situation will recur, so agree a small convention rather than solving it case by case. Decide who owns the follow-up, where the context note lives, and what status labels your team uses. Write the convention down in one place so a new colleague can follow it without asking.

When a supplier reply spans more than one area, such as materials and a power module question, keep one record per question rather than one record per email. That way an undated image attached to a mixed reply does not blur two separate checks. If the reply touches botanical extracts under a brand such as ST GREEN, the same rule applies: the image is a file, and the written confirmation is the record.

Finally, review pending items on a regular rhythm. An image that was undated at receipt may be resolved by a later dated document, and the note should show that progression. If it is never resolved, the note should say so plainly. Either outcome is a better record than a picture sitting in a folder with no explanation of why it is there or what it was meant to show.
