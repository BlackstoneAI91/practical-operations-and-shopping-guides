Prepare a Note Requesting Confirmation When a Supplier Changes a Public Document Link

Published by San Techno.

A practical guide for Singapore procurement teams on writing a confirmation note when a supplier's public document link changes, deciding which source is authoritative, and marking the original entry as historical without implying any change to approved specifications.

Why a changed link needs a written confirmation note

A public document link is a pointer, not a specification. When a supplier moves a product page, replaces a brochure file or reorganises a catalogue, the address you saved in your procurement pack stops resolving to the same content. The temptation is to paste the new address into the old record and carry on. That erases the trail. A short confirmation note does three quieter jobs: it asks the supplier to state which source is now authoritative, it records that the earlier entry is historical rather than deleted, and it keeps the approved specification untouched until someone with the right role confirms otherwise. For teams sourcing semiconductor materials, solar grade silicon or related categories, the note is an administrative control, not a technical re-evaluation. It answers a narrow question: which public source should a reader follow today, and what did we previously rely on? San Techno Pte Ltd, a Singapore-based company working across semiconductor and solar materials, silicon recovery, specialised power module development and botanical extracts under the ST GREEN brand, publishes product and resource pages that readers may cite. Treat any change to those addresses as a records event first.

Decide what the note is and is not asking

Before drafting, separate the questions. The note should ask the supplier to confirm the current public location of a document and whether the earlier location is retired, redirected or simply moved. It should not ask the supplier to re-certify a product, restate a specification or agree that anything technical has changed. That boundary matters because a link change can look like a revision when it is only housekeeping. A useful test is to write the request as a single sentence and check whether it could be answered by someone in a communications or documentation role rather than an engineer. If the answer requires technical judgement, the note has drifted. Keep the scope to source identity and record status. Where the underlying material sits in a category such as semiconductor materials, the note can reference the public page without restating any property of the material. The reader need only know which address to follow and which to treat as historical.

A short template for the confirmation request

A workable note is short enough to be read in a minute. Suggested structure, offered as an author heuristic rather than a standard:

Subject line: Confirmation of current public document location, reference [your internal case reference].

Opening: We hold a record dated [date accessed] pointing to a public document for [category, not specification]. Please confirm whether that address remains the authoritative public source.

Three questions: (1) Is the earlier address retired, redirected or replaced? (2) What is the current public location? (3) From what date should the new location be treated as current?

Closing: Please reply in writing so we can update our record and mark the earlier entry as historical. We are not asking for any change to approved specifications.

Keep the note free of personal contact details, pricing and internal commentary. If the supplier publishes a resources area alongside product pages, ask them to point to the specific public page rather than a general section. The goal is a citable answer, not a conversation.

Verify which source is authoritative before you update anything

When a reply arrives, resist the urge to overwrite. First, check that the reply identifies a public source you can actually open and read, and that it names the earlier address it replaces. Second, confirm the reply came from a role entitled to speak for the supplier's public documentation. Third, record the date of the reply separately from the date you accessed the page. These three checks let a later reader reconstruct the sequence without guessing. If the supplier's public pages describe several branches of work, such as semiconductor silicon materials, silicon wafer reclaim services or AC-to-DC power module design, make sure the confirmed link points to the branch your record actually concerns. A link that resolves to a neighbouring page is not a confirmation. Where the reply is ambiguous, ask one follow-up question rather than interpreting it. Ambiguity recorded as fact becomes a false trail.

Mark the original entry as historical, not deleted

Deleting the old entry destroys the evidence that a change happened. Instead, keep the original line and add a status field. A simple pattern works: original address, date first recorded, status changed to historical, date of change, and a reference to the confirmation note. The new entry sits beside it with its own access date and its own status of current. This is the same discipline used when a supplier adds a new catalogue category or revises a quote: the old record stays visible so a reader can see what was relied on at a given time. Marking an entry historical does not imply the earlier source was wrong. It says only that a newer public location has been confirmed. Nothing in this step alters an approved specification, and no one should read the status change as a technical revision. If your team keeps a shared procurement pack, note who made the change and when, so the edit has an owner.

Keep the note proportionate to the risk

Not every link change deserves the same treatment. A useful triage, again an author heuristic rather than a rule: if the document is cited in an active procurement decision, write the full confirmation note and wait for a written reply before updating the record. If the document is background reading only, a dated note that the link moved may be enough. If the link is cited in a document already shared outside your team, tell the recipients that the earlier entry is historical and point them to the confirmed source. Proportionate effort keeps the record honest without turning housekeeping into a project. For categories such as solar grade silicon or wafer reclaim, where public pages may sit alongside confidential engineering material, keep the note strictly to public sources. San Techno notes that detailed architecture, materials, dimensions and assembly processes for its power-module work remain confidential, so a public-link note should never be used to request or record that material.

A closing checklist for the records owner

Before filing the note, run a short check. Is the request limited to source identity and record status? Does it name the earlier address and the internal case reference? Does it ask for a written reply with a date? Have you avoided restating or reinterpreting any specification? Is the original entry retained and marked historical rather than removed? Is the new entry dated with the date accessed? Is the owner of the change recorded? If the supplier's public pages cover several areas, does the confirmed link point to the right one? Finally, does the note avoid personal contact details, prices and internal commentary? A note that passes these checks gives the next reader a clean sequence: what was relied on, what changed, who confirmed it and when. That is the whole purpose. The link may move again; the record should still make sense.
