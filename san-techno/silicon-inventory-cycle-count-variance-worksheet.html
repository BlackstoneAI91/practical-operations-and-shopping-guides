Silicon Inventory Cycle Count Variance Worksheet: A Worked Guide for Procurement Teams

Published by San Techno.

A practical, worked worksheet for Singapore procurement teams counting silicon inventory, recording variances, and deciding whether to recount, adjust, or escalate before the period closes.

Why a Cycle Count Variance Worksheet Matters for Silicon Stock

Silicon inventory does not behave like a box of fasteners. A bin may hold wafers in cassettes, packaged material, or prepared stock, and each line can carry a different unit of measure, a different lot reference, and a different owner. When a cycle count disagrees with the system record, the disagreement is not automatically an error in the count or an error in the record. It is a signal that needs a documented decision.

This guide gives procurement and stores teams a repeatable worksheet for that decision. It is written for Singapore-based buyers and receiving staff who source, receive and document semiconductor materials and solar grade silicon, and who need the count file to stand up when the period closes and someone else reviews it.

The worksheet does three things. It captures the count in a structured way, it records the variance with a reason code, and it routes the line to one of three outcomes: recount, adjust, or escalate. The aim is not to eliminate variances. The aim is to make each variance explainable and owned.

One piece of context is worth stating plainly. San Techno has worked with semiconductor and solar materials since its incorporation in 2006, beginning as a wholesaler and distributor of semiconductor- and solar-grade silicon materials. That background is why the worksheet below treats lot identity and unit-of-measure discipline as first-class fields rather than afterthoughts.

Setting Up the Worksheet Header Before Anyone Counts

Most count disputes start before the counter reaches the shelf. If the header is vague, the line data cannot be trusted. Fill the header in first, and do not let the count begin until it is complete.

Header fields to capture:

Count reference: a unique identifier for this count event, for example CC-2025-014. Count date and cut-off time: the exact moment the system snapshot was taken. A count taken at 09:00 against a snapshot at 17:00 the previous day will show movement that is not a variance. Location and bin: the physical position, written the same way every time. Material description and grade: for example solar grade silicon, packaged wafers, or prepared inventory. Unit of measure: wafers, pieces, cassettes, kilograms, or packages. State it explicitly. A count in cassettes compared against a record in wafers is a unit error, not a stock loss. System quantity at cut-off: the book figure, copied, not retyped from memory. Counter name and role: who physically counted. Checker name and role: who independently verified, where a second person is used.

A short note on the cut-off. If your site cannot freeze movement during the count, record every movement that occurred between the snapshot and the physical count on a separate movement log and attach it. The worksheet should reference that log rather than absorb it.

Keep the header identical across all lines in the count. If a line needs a different cut-off, it belongs in a separate count event with its own reference. Mixing cut-offs inside one worksheet is the most common reason a variance cannot be closed cleanly.

The Line-Level Count Record

Each physical line gets one row. The row should be readable by someone who was not present.

Line fields:

Line number. Lot or batch reference, copied from the label, not inferred. Package or container count, and the quantity inside each. Counted quantity, in the stated unit of measure. Count method: full count, weigh count, or sample-based estimate. If any line is estimated rather than counted, say so. An estimate presented as a count is a documentation failure waiting to surface. Condition note: for example, a damaged outer package, a missing label, or a cassette that does not match the lot reference. Photo reference: the file name of any photo taken, so the image can be found later.

A worked example, entirely fictional:

Line 4. Lot reference SL-2291. Six cassettes, each recorded as 25 wafers. Counted quantity 148 wafers. Count method: full count. Condition note: one cassette label unreadable. Photo reference: CC-2025-014-L4-a.jpg.

System quantity for that line: 150 wafers. Variance: minus 2 wafers. That is the raw number. The next section turns it into a decision.

Two habits keep this section honest. First, write the lot reference exactly as printed, including any suffix. Second, never overwrite a first count with a second. Add a new row and mark the first as superseded, so the audit trail shows both.

Recording the Variance and Assigning a Reason Code

The variance is simple arithmetic: counted quantity minus system quantity, in the same unit of measure. What matters is the reason code attached to it.

A short, closed list of reason codes works better than free text. An example set:

RC1 Unit-of-measure mismatch. RC2 Cut-off or timing difference. RC3 Label or lot reference discrepancy. RC4 Physical damage or breakage noted at count. RC5 Counting error suspected. RC6 Record error suspected. RC7 Unexplained, pending investigation.

Each line carries exactly one primary code. If a line genuinely has two causes, record the primary code and note the secondary in the comment field rather than splitting the line.

Returning to the fictional line 4: variance minus 2 wafers, primary code RC3, because one cassette label was unreadable and the lot could not be fully confirmed. Comment: label illegible, cassette set aside for verification.

A second fictional line shows a different path. Line 7, lot reference SL-2304, counted 96 kilograms against a system figure of 100 kilograms. Variance minus 4 kilograms. Primary code RC2, because a movement was recorded after the snapshot and before the count. The movement log reference is attached. That line is not a loss; it is a timing artefact, and the code says so.

Reason codes are the difference between a variance report and a variance investigation. Without them, every discrepancy looks the same and the reviewer has to redo the thinking.

The Decision Rule: Recount, Adjust, or Escalate

Every line ends in one of three outcomes. Write the rule down before the count so the decision is not made under pressure.

Recount. Use this when the variance could plausibly be a counting error: a high-value line, a line counted by estimate, a line with an unreadable label, or any line where the counter and checker disagree. A recount is a fresh physical count by a different person where possible, recorded as a new row. Do not recount the same line more than twice without escalating.

Adjust. Use this when the cause is identified and documented, and the correction is a record correction rather than a physical one. A unit-of-measure mismatch that is fully explained, or a timing difference supported by a movement log, is an adjust case. The adjustment note should state the cause, the evidence reference, and who approved it.

Escalate. Use this when the variance is unexplained, when the value or quantity crosses a threshold your team has set, when a lot reference cannot be reconciled at all, or when the same reason code keeps appearing on the same material across counts. Escalation means the line goes to a named owner with a due date, not into a pending pile.

A simple threshold example, offered as an author heuristic rather than a rule: recount any line with a variance above two percent of the system quantity, and escalate any line above five percent or any line with an unresolved lot reference. Set your own numbers and write them into the worksheet header so the rule travels with the file.

For material that is being set aside rather than returned to stock, the decision may involve a recovery route rather than a simple adjustment. San Techno helps recover non-usable silicon from integrated-circuit fabs, silicon wafer manufacturers, solar cell companies and chip packaging facilities, and those materials can be processed into reusable raw materials for solar wafers and cells. Where a count line concerns material destined for that route, record the route reference on the line so the stock record and the recovery record can be matched later.

Closing the Period: Sign-Off and the Variance Summary

A worksheet is not closed when the counting stops. It is closed when the summary is signed and the open items have owners.

The summary page should show:

Total lines counted. Lines with zero variance. Lines by reason code, with counts and quantities. Lines resolved by recount, by adjustment, and by escalation. Open escalations, each with a named owner and a due date. Approver name, role, and date.

Two closing habits are worth building in. First, keep the original count rows visible even after adjustment. A summary that shows only the final numbers hides the work and makes a later review harder. Second, write a one-paragraph note on any reason code that appeared more than once in the period. That note is what turns a monthly count into a trend you can act on.

A fictional closing note might read: RC3 appeared on three lines this period, all involving unreadable cassette labels on the same incoming lot. Raised with receiving for a label check at intake.

That single sentence is more useful to the next reviewer than a page of totals, because it points at a cause rather than a number.

A Blank Worksheet You Can Copy

The fields below are a starting template. Adapt the labels to your own system, but keep the structure.

Header: count reference; count date; cut-off time; location; material description and grade; unit of measure; system quantity at cut-off; counter name and role; checker name and role; variance thresholds used.

Line: line number; lot or batch reference; package count; quantity per package; counted quantity; count method; condition note; photo reference; system quantity; variance; primary reason code; comment; decision (recount, adjust, or escalate); decision owner; due date.

Summary: total lines; zero-variance lines; lines by reason code; resolved by recount; resolved by adjustment; open escalations with owners; approver name, role, and date; period note on repeated reason codes.

A few practical reminders for Singapore procurement teams. Keep the unit of measure visible on every line, because mixed units are the most common source of false variances. Record the cut-off time, because movement during a count is normal and should be logged rather than argued about. And treat the reason code as the most important field on the row, because it is the one that lets a reviewer understand the line without calling you.

Used consistently, the worksheet does not just record a count. It builds a short, defensible history of how your silicon stock moved and why, which is exactly what a period close and a later audit will ask for.
