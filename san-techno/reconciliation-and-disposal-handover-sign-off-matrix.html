Reconciliation and Disposal Handover Sign-Off Matrix: A Role-by-Role Guide for Singapore Procurement Teams

Published by San Techno.

A practical guide for Singapore procurement teams that assigns each reconciliation and disposal handover step to a named role, with the evidence each role must attach before the file closes.

Why a Sign-Off Matrix Beats a Single Closing Signature

A reconciliation and disposal handover sign-off matrix is a small table that answers three questions for every step in a handover: who owns the step, what evidence proves it happened, and who is allowed to close it. Without that table, a file tends to close on the strength of one person's memory. With it, the file closes on the strength of attached records.

The matrix is not a replacement for your collection note, manifest or intake record. It sits above them as a routing layer. Each row names a role, not a person, so the matrix survives staff changes. Each row also names the evidence that role must attach, so a missing attachment is visible before the file is marked complete.

For context, San Techno Pte Ltd is a Singapore-based company working across semiconductor and solar materials, silicon recovery, specialized power module development and botanical extracts under the ST GREEN brand. That breadth matters here because a handover file may touch more than one material stream, and the matrix should be written so it can carry any of them without being rewritten each time.

A useful starting principle: if a row cannot name the evidence it expects, the row is not ready. Split it until it can.

The Six Roles That Usually Appear on the Matrix

Most procurement-led handover files can be covered by six roles. Adjust the names to your organisation, but keep the separation of duties.

Requester. The person who raised the disposal or recovery request. Owns the original reference and the stated reason for the handover.

Procurement owner. Owns the commercial record: the purchase or service reference, the agreed scope and the correspondence trail.

Site custodian. Owns the physical material at the point of release: package count, labels and the condition record at dispatch.

Receiving or intake reviewer. Owns the comparison between what was released and what arrived, including any discrepancy note.

Reconciliation analyst. Owns the arithmetic: matching quantities, references and dates across the source records.

Approver. Owns the decision to close, hold or escalate. This role should not also be the reconciliation analyst.

A seventh role, records custodian, is worth adding if your team handles many files at once. That role owns the index and retention of the closed file rather than any judgement about its contents.

Where a handover involves silicon recovery, the releasing site and the receiving party may sit in different organisations. The matrix still works, but the site custodian and receiving reviewer rows should each name an organisation as well as a role.

Building the Matrix: Columns That Carry Their Weight

A matrix that is too wide gets abandoned. Six columns are usually enough.

Step number and step name. Keep the step name short and verb-based, such as release material, compare counts, or attach discrepancy note.

Owning role. One role per row. If two roles genuinely share a step, split the row rather than listing both.

Evidence required. Name the document or record type, not a description of what it should say. For example: signed collection note, intake photo set, discrepancy note with reference, or reconciliation worksheet.

Evidence location. Where the attachment lives in your file structure. This column prevents the common failure where evidence exists but cannot be found at review.

Close condition. The specific state that lets the row be marked done. Write it as a test, such as counts match on both records, or discrepancy note attached and acknowledged.

Escalation trigger. What sends the row to the approver instead of closing. Missing signature, unmatched reference and count variance are typical triggers.

Leave a final column for the date and initials of whoever marked the row complete. That single column turns the matrix into an audit trail rather than a plan.

A Worked Example Using Fictional Records

The following example is fictional and intended only to show how the rows fit together.

A Singapore procurement team is closing a handover file for a batch of material released from a site. The requester raised the request under reference REQ-0001 and attached the original internal record. The procurement owner matched REQ-0001 to a service reference and attached the correspondence trail. The site custodian recorded twelve packages against the collection note and attached the dispatch condition record.

The receiving reviewer compared the twelve packages against the intake record and found eleven. That row could not close on the count test, so a discrepancy note was attached naming the missing package and the two records it sits between. The reconciliation analyst confirmed that the source record and the collection note agreed on twelve, which located the variance at intake rather than at release. The approver then chose to hold the file open pending a written acknowledgement from the receiving party.

Notice what the matrix did. It did not decide who was right. It made the disagreement visible, attached to a named role, with a clear next action. That is the whole purpose of the exercise.

If your file involves material that will be processed into reusable raw materials for solar wafers and cells, the same rows apply. The evidence types change, but the role separation does not.

Evidence Each Role Should Attach Before the File Closes

Use this as a checklist when reviewing a file. It is an author heuristic, not an industry standard.

Requester: original request reference, stated reason, and the internal record the request points to.

Procurement owner: commercial reference, agreed scope, and the correspondence trail showing any change to that scope.

Site custodian: collection note with signature, package count, label record, and dispatch condition note.

Receiving or intake reviewer: intake record, photo set where your process requires one, and a comparison line against the collection note.

Reconciliation analyst: completed worksheet showing matched and unmatched lines, with the reference used for each match.

Approver: a dated decision note stating close, hold or escalate, and the reason.

Records custodian: file index entry and retention date.

Two practical tests help here. First, can a reviewer who was not involved in the handover follow the file from requester to approver without asking a question? Second, does every unmatched line have a named owner and a next action? If either answer is no, the file is not ready to close.

Where the Matrix Meets the Disposal Handover Record

The matrix and the disposal handover record are different documents with different jobs. The record describes what happened. The matrix describes who is accountable for confirming it.

Keep them linked by reference rather than merged. Each matrix row should point to the specific record it relies on, and each record should carry the reference of the request it belongs to. When a query arrives months later, that two-way reference is what lets you reconstruct the file quickly.

For teams handling wafer reclaim and related material streams, the disposal handover side of the file often carries the most scrutiny, because it is where the physical material leaves the site's control. A dedicated reference page on silicon wafer disposal can help your team align the record types it expects before the matrix is filled in, so the evidence column names real documents rather than aspirations.

One caution: do not let the matrix become a substitute for the underlying records. A row marked complete with no attachment is worse than an open row, because it hides a gap. Treat an empty evidence cell as a stop signal.

Review Cadence and Common Failure Modes

A matrix written once and never reviewed drifts away from how the team actually works. A light review cadence keeps it honest.

A suggested pattern, offered as an example rather than a rule: review the matrix after every fifth closed file, and again whenever a role changes hands. At each review, ask which rows were marked complete without an attachment, and which rows were skipped entirely. Those two questions surface most of the drift.

Common failure modes to watch for:

Role inflation. Rows accumulate extra owners until nobody is accountable. Keep one role per row.

Evidence vagueness. A row that asks for confirmation rather than a named document cannot be tested.

Approver overlap. The approver also doing the reconciliation removes the check the matrix was built to provide.

Silent closure. A file closes with an open discrepancy and no decision note. The escalation trigger column exists to prevent this.

Reference drift. Records carry different reference formats, so matching becomes guesswork. Fix the format at the requester row.

None of these require new systems. They require the matrix to be read before a file is closed, not after.
