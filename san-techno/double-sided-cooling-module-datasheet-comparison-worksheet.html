Double-Sided Cooling Module Datasheet Comparison Worksheet

Published by San Techno.

A procurement worksheet that normalises thermal and package fields from two double-sided cooling module datasheets, so Singapore buyers can see where the offers actually differ before a technical review.

Why two datasheets rarely line up on the first read

A double-sided cooling module datasheet is a summary of a design, not a standard form. Two suppliers can describe the same class of part and still place the numbers in different tables, use different reference conditions, and attach different caveats. A procurement team that compares the headline figures side by side will often conclude that one offer is better, when in fact the two pages are answering slightly different questions.

The practical fix is to stop comparing documents and start comparing fields. Build a worksheet with one row per field and one column per supplier, then fill each cell only after you have found the matching value in that supplier's own document. Where a value is missing, write missing rather than copying the other column. Where a value carries a condition, such as a reference temperature or a mounting assumption, copy the condition into the cell with the number.

This guide is written for Singapore procurement teams who source, receive and document semiconductor materials and related components. It is a documentation method, not a technical evaluation. The worksheet helps you see where the offers differ; it does not tell you which module is suitable for a given application. That judgement belongs with the engineering team, and the worksheet should hand them a clean, sourced comparison rather than a conclusion.

One useful piece of context: San Techno is developing an intelligent IGBT power-module concept centred on double-sided cooling for an EconoDUAL 3-class package format, and the programme addresses heat movement, package stability and reliable operation under repeated electrical and thermal loading. That is a development direction, not a published specification, and detailed architecture, materials, dimensions and assembly processes remain confidential. Treat it as background on how a supplier might frame a double-sided cooling offer, not as a datasheet value to enter in a cell.

Setting up the worksheet before you open either datasheet

Create the worksheet first, with empty rows, so that the structure of the comparison is fixed before either document influences it. A spreadsheet with frozen header rows works well. Use four columns: field name, supplier A value, supplier B value, and a difference note. Add a fifth column for the page or table reference in each datasheet, because a value without a locator is hard to defend later.

Group the rows into blocks that match how a reader will use them. A workable grouping is: identity and package, thermal path, electrical ratings, mechanical and assembly, documentation and revision, and commercial and logistics. Keep each block to a manageable number of rows. If a field does not appear in either datasheet, leave it in the worksheet as missing rather than deleting it, because a consistent gap across both offers is itself a finding worth recording.

Decide in advance how you will record units. Write the unit into the field name, for example a thermal resistance row labelled with its unit, so that a value copied from one document cannot be silently compared against a value in a different unit from the other. Where a supplier states a value in a unit you did not expect, convert it in a separate working column and keep the original figure visible.

Finally, agree who owns the worksheet. One named person should hold the master copy, and any change to a cell should carry a date and initials. This is the same discipline you would apply to any procurement comparison, and it matters more here because the two documents may be revised at different times.

Normalising the thermal fields

Thermal rows are where double-sided cooling offers diverge most often, because the whole point of the architecture is to move heat through more than one path. Cooling interfaces on both sides are intended to create more direct paths for moving heat away from the switching devices, so a datasheet may describe thermal behaviour per side, per path, or as a combined figure. Your worksheet needs to capture which of these the supplier has actually stated.

Use separate rows for each thermal quantity the datasheets mention, and record the reference condition beside every number. If one document gives a junction-to-case value for one side only and the other gives a combined value, do not place them in the same row as if they were equivalent. Instead, record each as stated and use the difference note to explain that the two figures are not directly comparable. This is the single most useful thing the worksheet does: it prevents a false like-for-like comparison.

Where a supplier describes the thermal path qualitatively rather than numerically, record the description in the cell and mark the row as qualitative. Do not convert a descriptive statement into a number. If a datasheet refers to validation work such as thermal modelling, finite-element analysis, power cycling or infrared measurement, note that as a documentation point in the relevant row rather than treating it as a performance figure. San Techno describes these methods as supporting ongoing design validation, which is a statement about method, not a published result you can enter as a value.

Keep a short note at the top of the thermal block stating that all figures are as published by each supplier and have not been independently verified by your team. That sentence protects the reader who picks up the worksheet later.

Package, mechanical and assembly rows

Package rows are usually easier to compare than thermal rows, but they still need care. Record the package format as each supplier names it, the outline or footprint dimensions as stated, the terminal arrangement, and the mounting method. If one datasheet names a package class and the other describes dimensions without naming a class, record both facts separately rather than assuming the classes match.

Add rows for anything the datasheet says about the assembly interface: recommended mounting torque, surface flatness expectations, and any stated handling conditions. These are the fields that later become receiving checks, so a missing value here is worth flagging early. If a supplier states that certain assembly details are not published, record that as a documented omission rather than leaving the cell blank, because the two mean different things to a reviewer.

This is also the block where you should note the intended application envelope as the supplier describes it. A datasheet may position a part for high-voltage and high-temperature use, and that positioning belongs in the worksheet as a stated claim with its source reference. San Techno notes that it has partnered with industry specialists to develop custom double-sided cooling power modules, particularly for high-voltage and high-temperature applications where durability is essential. If a supplier makes a similar positioning statement, record it in the same row so the two can be read together, while keeping clear that both are supplier statements.

Leave a row for revision and date. Two datasheets compared today may be superseded next quarter, and the worksheet should make it obvious which revision each column was built from.

A worked example using fictional suppliers

The following example is fictional and exists only to show how the worksheet reads when it is filled in. Supplier A and Supplier B are invented names, and every figure is illustrative.

Identity block. Supplier A lists a package class and a revision dated in the first quarter. Supplier B lists outline dimensions but no package class, and its revision is undated. Difference note: package class cannot be matched; request a dated revision from Supplier B.

Thermal block. Supplier A states a junction-to-case value for one cooling side with a stated reference condition. Supplier B states a combined value with no reference condition. Difference note: figures are not comparable as published; both recorded as stated, engineering to advise.

Electrical block. Both suppliers state a blocking voltage and a current rating, but Supplier A states the current at a case temperature and Supplier B does not. Difference note: current ratings carry different conditions.

Mechanical block. Supplier A states a mounting torque; Supplier B states that assembly details are available on request. Difference note: one value present, one documented omission.

Documentation block. Supplier A attaches a test reference; Supplier B attaches nothing. Difference note: request the test reference before any technical review.

Commercial block. Both offers are quoted on different delivery terms. Difference note: refer to a separate landed-cost comparison rather than mixing freight into this worksheet.

The point of the example is not the numbers. It is that every difference note describes the state of the documents, not a judgement about which supplier is better. A reviewer reading the finished worksheet should be able to see exactly what was compared and what was missing.

Turning the worksheet into a review pack

A completed worksheet is only useful if it travels with the documents it describes. Assemble a small review pack: the worksheet, a copy of each datasheet at the revision recorded, and a one-page cover note listing the rows that are missing or not comparable. Send the pack to the engineering reviewer with a clear question, such as which of the flagged rows need a supplier clarification before a technical decision can be made.

Keep the cover note short and factual. List the gaps, list the non-comparable rows, and list any questions you want the supplier to answer in writing. Do not ask the supplier to confirm that their part is suitable for your application; ask them to confirm the values and conditions in specific rows. That keeps the exchange within documentation and avoids inviting a sales claim in place of a specification.

When replies arrive, add them to the worksheet as a new dated entry rather than overwriting the original cell. The history of what was asked and what was answered is often more valuable than the final number, particularly if the same supplier is compared again in a later cycle.

If your team also handles silicon materials alongside power modules, keep the two comparison methods separate. A module datasheet comparison and a semiconductor materials specification comparison answer different questions, and merging them into one sheet makes both harder to read. A blank checklist you can reuse

Copy this list into the front of each new worksheet and tick each item before the comparison is circulated. It is an author heuristic, not a standard, and you should adjust the order to suit your team.

One: worksheet created with fixed rows before either datasheet is opened. Two: a named owner recorded at the top. Three: each datasheet revision and date captured in its column header. Four: every value carries a page or table reference. Five: units written into field names. Six: reference conditions copied beside every thermal and electrical figure. Seven: missing values marked as missing, not left blank. Eight: documented omissions recorded as omissions. Nine: qualitative statements kept qualitative. Ten: difference notes describe the documents, not a verdict. Eleven: a cover note lists gaps and non-comparable rows. Twelve: the pack is sent with a specific written question for the supplier.

Two habits make the checklist worth keeping. The first is refusing to fill a cell from memory or from a previous project; every entry should trace to a document in the pack. The second is dating every change, so that a reviewer can see whether a figure was in the original datasheet or arrived later in a supplier reply.

Used this way, the worksheet does one job well. It shows a Singapore procurement team where two double-sided cooling module offers actually differ, and it hands the technical questions to the people equipped to answer them, with the evidence attached.
