Procurement Note When an AC-to-DC Power Module Design Changes

Published by San Techno.

A practical note template for Singapore procurement teams that records what changed in an AC-to-DC power module design, which documents were reissued, and what purchasing must confirm before the next order.

Why a design change needs its own procurement note

A design change on a power module rarely stays inside engineering. It reaches procurement as a set of small, easy-to-miss differences: a revised drawing, a new revision letter on a datasheet, a changed part reference on a purchase order, or a supplier email that says the previous version is superseded. If those differences are not captured in one place, the next order can be placed against a document that no longer describes what is being built.

The purpose of this note is narrow. It is not an engineering change record and it is not a quality report. It is a short procurement-side document that answers three questions before the next purchase order is raised: what changed, which documents were reissued, and what purchasing must confirm with the supplier and with internal engineering. Keeping it short matters, because a note that takes an hour to write will not be written at all.

San Techno works on AC-to-DC power module design as one of its technical areas, alongside semiconductor materials and silicon recovery work. That context is useful for readers because it shows the kind of supplier conversation this note is designed to support: a design-led discussion where the commercial paperwork has to keep pace with the technical one. The note below is a buyer-side tool and does not describe any supplier's internal process.

A useful habit is to open the note the same day a change is first mentioned, even if the details are incomplete. An incomplete note with open questions is more useful than a perfect note written after the order has already gone out.

What counts as a design change for procurement purposes

Procurement teams do not need to judge whether a change is technically significant. They need to judge whether it affects what they order, what they receive, or what they can prove later. A simple filter helps: if the change touches any field that appears on a purchase order, a receiving check, or a supplier document, it belongs in the note.

Typical triggers include a revised revision letter on a datasheet, a change to a package or mounting reference, a new or withdrawn part number, a change in the documents supplied with each shipment, and any statement from the supplier that earlier documentation should no longer be used. A change in test or validation evidence can also matter, because it may alter what the buyer expects to see on file.

For power modules, the technical direction can involve several interacting concerns. San Techno's stated development direction for its intelligent IGBT power-module concept considers the complete thermal path, material-layer expansion, packaging stress and assembly integrity, and the programme addresses heat movement, package stability and reliable operation under repeated electrical and thermal loading. A buyer does not need to evaluate those topics, but knowing they exist explains why a supplier may reissue documents in stages rather than all at once. The note should record which stage the buyer is currently working from.

One practical rule: record the change as the supplier described it, in the supplier's own words, then add a separate buyer interpretation line. Mixing the two makes later review harder.

The note template: header fields

The header is where most disputes are avoided. Keep it to a small fixed set of fields so that notes from different buyers can be compared.

Suggested header fields, offered as an example structure rather than a standard:

Note reference and date opened. Use a simple sequence that ties to the project, not to the supplier's numbering. Project or application name, as used internally. Supplier name and the contact role involved, without personal details in the shared copy. Original document set: list each document by title and revision as it stood before the change. Change trigger: how the buyer learned of the change, and on what date. Current status: open, pending supplier confirmation, pending internal approval, or closed. Owner: the named procurement role responsible for the next action.

Two fields deserve emphasis. The original document set matters because a change is only meaningful relative to a baseline, and buyers who skip the baseline later cannot show what they were working from. The change trigger matters because it separates changes the supplier announced from changes the buyer noticed, and the two need different follow-up.

Keep the header on one screen. If it spills onto a second page, the fields are probably too granular for a working note.

The change log: one row per difference

Below the header, keep a simple table with one row per difference. Columns that work well in practice include: item affected, before, after, source of the information, document reissued yes or no, and action owner.

The before and after columns should hold short factual entries, not narrative. For example, a revision letter moving from one value to another, a part reference being replaced, or a document being withdrawn. The source column records where the buyer saw the change, such as a supplier letter, a revised datasheet, or a meeting note. This is the column that protects the buyer later, because it shows the change was not invented internally.

The document reissued column is often left blank in a hurry, and that is a mistake. A change that has been announced but not yet reflected in a reissued document is a live risk for the next order. Marking it clearly lets purchasing hold the order or proceed with a written caveat.

A fictional example shows the shape. Suppose a buyer records that a supplier's module documentation moved to a new revision, that the accompanying test summary was reissued on the same date, and that the packing list format was unchanged. Three rows, three clear statuses, and a short list of what still needs confirming. That is enough for a working note.

Where a supplier's design work is still in development, buyers should expect that some details will not be shared. San Techno states that detailed architecture, materials, dimensions and assembly processes for its power-module work remain confidential, and a procurement note should respect that boundary rather than press for detail that will not be provided.

What purchasing must confirm before the next order

The confirmation section is the part of the note that actually changes behaviour. It should list, in plain terms, what must be true before the next purchase order is released.

A workable confirmation list, again as an example rather than a standard:

Engineering has confirmed in writing that the new revision is the one to order. The supplier has confirmed which documents now apply and which are withdrawn. The purchase order description matches the current document set, including revision references. Receiving has been told what to expect on the packing list and in the accompanying paperwork. Any open question has a named owner and a date by which it will be answered.

Two of these are commonly skipped. The receiving briefing is easy to forget because receiving is not in the design conversation, yet it is the team that will first notice a mismatch. The written engineering confirmation is also sometimes assumed rather than obtained, which leaves procurement exposed if the change is later reversed.

Where a supplier offers design validation work, it helps to know what evidence may accompany a change. San Techno notes that thermal modelling, finite-element analysis, power cycling and infrared measurement support ongoing design validation. For a buyer, the practical point is not to interpret those methods but to ask which validation documents, if any, will be reissued alongside the design change, and to record the answer in the note.

Reissue tracking and document control

A design change is only closed when the paperwork has caught up. The reissue tracking section of the note should list each document that needs to be replaced, the revision it moves to, the date received, and where the current copy is stored.

A simple status scale works better than free text. For example: not yet requested, requested, received, checked against the change log, and filed. The checked step matters because a reissued document can arrive with a different revision letter but the same content, or with a change that was not in the original announcement. A quick comparison against the change log catches both.

Buyers should also record which documents were not reissued. A short line saying that a particular document was confirmed as unchanged is valuable evidence later, and it prevents the same question being asked again at the next review.

For teams that handle several material categories, the same discipline carries across. San Techno's work spans semiconductor materials, silicon recovery and solar-related material streams, and buyers who order across more than one category often find that a single note format, applied consistently, is easier to audit than separate formats per category. The format does not need to be elaborate; it needs to be the same each time.

Closing the note and handing it on

A procurement note should end with a short closure block: the date the last open item was resolved, the role that confirmed closure, and a one-line summary of what the next order will reference. That summary line is what a colleague picking up the file six months later will read first.

Closure does not mean the note is archived and forgotten. If the same supplier later announces another change, the new note should reference the previous one rather than start from nothing. A chain of short notes is far easier to follow than one long document that has been edited repeatedly.

A final practical point concerns scope. This note covers procurement documentation only. It does not cover technical approval, safety assessment or regulated handling, which belong to other processes and other owners. Keeping the boundary clear protects the note's usefulness, because readers know exactly what it does and does not claim.

For buyers who want to see how this fits alongside the company's wider technical and materials work, the resources area and the products area are the natural next places to look. The note template above is deliberately plain so that it can be adapted to whatever document set a given supplier uses, without needing new fields for every project.
